# Публичное отслеживание заказа: недостающий серверный контракт

Текущий клиент не содержит публичного метода загрузки заказа. Маршрут
`/#/track/:id` читает локальный Zustand-store, поэтому ссылка сама по себе
не даёт клиенту на другом устройстве доступ к заказу. Фронтенд больше не
показывает выдуманную дату доставки «создан + 3 дня».

Для полноценного исправления требуется подтвердить или добавить в отдельном
бэкенде следующий контракт (это предложение, а не существующий endpoint):

- Создание и отзыв непрозрачного токена отслеживания сотрудником с доступом к заказу.
- Публичный `GET /v1/public/tracking/:token`, без входа в кабинет.
- Ответ: номер заказа, текущий статус, история статусов с датами, название
  компании и согласованная дата доставки либо `null`.
- Не передавать внутренние ID, цены закупки, баланс клиента, телефон или полный
  адрес. Состав заказа и суммы включать только после согласования назначения ссылки.
- Недействительный или отозванный токен: `404`; ограничение частоты: `429`.

После подтверждения контракта клиент должен получать данные этим методом,
показывать загрузку/ошибку и создавать ссылки по токену, а не по ID из localStorage.
