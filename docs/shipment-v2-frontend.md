# Shipment v2 frontend

Only protected, server-confirmed commercial orders are eligible. This stage supports the
existing backend subset: unpaid credit to a real customer, no discount, no money received,
no VAT breakdown/extra credit terms/marked goods and exact line/total amounts.
Backend remains authoritative for catalog, existing payments, debt and actual posting.

Preparation is an online-only existing status transition to picking. Its result is not applied
optimistically: the current native order is fetched and durably saved in scoped authority storage.
If the response is lost, reload obtains actual server status. No stock/money/debt is changed by
this preparation. The legacy status endpoint is never used for protected shipped or delivered.
Protected delivered remains explicitly blocked in this stage, including the Delivery page.

Shipment requires explicit active warehouse selection and no unresolved same-order command.
The full original body `{contractVersion:2,status:'shipped',shipmentId,warehouseId,orderSnapshot}`
is durably accepted by the existing immutable outbox before any optimistic stock projection.
Root key is `order_status`; root ID is the URL orderId. Shipment UUID is generated once by
businessIntent; the stable HTTP key is `shipment:<shipmentId>`. Retry never reconstructs body.
An unsuccessful durable write reports failure; the intent retains the UUID for retry.

Dependency resources include orderId and every warehouse/product pair. Existing DAG barriers,
quarantine, scoped journals and Web Locks remain in force. Pending shipment blocks commercial
editing, another shipment and status shortcuts, including from another tab or after reload.
Historical commands are not changed; legacy orders retain the previous implementation.

Reconciliation sends the identical HTTP body, kind order_status, commandId=URL orderId and the
saved key. Shipment stock is projected exclusively against a fully verified warehouse snapshot.
qtyBase is already in base units: no second packaging conversion. Applied in that same snapshot
skips local deduction. A transport receipt alone never substitutes for a shipment stock proof.
Conflict/unverifiable/unknown coverage/quarantine with unresolved effect withholds precise stock.
not_observed is snapshot-local and never permits a new identity or removal of the old command.

Successful transport requires a verified fingerprint, exact identity/source-line mappings, zero
cash and expected debt amount; current native server order must also be persisted before ack.
This preserves newer status after replay. No local money or debt fact is generated by shipment.
409/422 quarantine retains original body/key and shows its diagnostic. Oversized reconciliation,
network and storage errors retain commands/snapshots; no approximation or hidden pagination occurs.

## Validation scope

Real Edge 156 production/SW scenarios use a fresh profile and isolated PostgreSQL fixtures:
UI commercial credit order -> confirmed snapshot -> preparation -> A40/B60 -> offline shipment
of two units -> offline reload -> A38/B60 -> applied -> API/SQL A38/B60. Lost committed HTTP
response and two real tabs are separate runs. Each adds one stock movement and one debt entry
for 200 RUB, zero money movements. Identical replay produces no additional entries.
Storage refusal, company/logout guards, dependency barriers, A/B selection and error resolutions
are automated tests, not claimed as browser failure-injection scenarios.

Final checks: frontend 689/689 (40 files); ESLint zero errors and 101 existing warnings;
production build passed. Backend typecheck and 456/456 regression tests (32 files) passed
against the isolated test PostgreSQL. All three Edge 156.0.4314.42 scenarios passed on the
final production bundle; the customer balance and count of posted shipment documents were
also checked. Each run has exactly one posted shipment and +200 RUB customer debt.

Readiness applies only to protected shipment v2. Historical legacy shipment behavior has not
been migrated or repaired here; its previous local-status path remains a separate risk.
